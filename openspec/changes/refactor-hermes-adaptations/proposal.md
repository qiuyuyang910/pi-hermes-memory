# Proposal

## Why

基于 Hermes 0.9.10 增加的角色、会话切换、恢复与回滚逻辑集中在 `src/index.ts`；会话归属和路径身份计算又分布在插件入口与 vendor 适配代码中。同一改动需要同时理解多组可变状态和生命周期顺序，增加维护及后续合并上游的成本。

## What Changes

- 将入口中的请求锁定、会话编排、交接记录和角色命令按职责分离，保留现有事件注册顺序、状态含义和失败处理。
- 复用现有归属模块中的路径身份与元数据解析，保留入口严格报错、历史搜索跳过不合法会话这两种既有策略。
- 明确 Hermes runtime、vendor 安装函数、历史清理与新增记忆日志的责任，保留 AsyncLocalStorage、关闭等待和现有持久化顺序。
- 全部本地新增代码及 vendor 适配均纳入范围判断；职责已经独立的角色解析、日志、清理和离线维护脚本保留现有边界，不为覆盖文件数而重写。
- 保持命令、工具、角色字段、配置、默认值、数据目录、会话元数据、数据库和日志格式不变。现有检索增强、direct-only 后台调用及禁用自动迁移/重建的策略继续保留。

## Capabilities

### New Capabilities

无。本次仅调整内部结构，`.openspec.yaml` 设置 `skip_specs: true`。

### Modified Capabilities

无。不改变用户可观察行为，不新增 delta spec。

## Impact

- 主要实施对象：`src/index.ts`、`src/storage.ts`、`src/hermes-runtime.ts`，以及设计中列出的职责模块和直接必要的 vendor 接入点。
- 上游范围依据：`SOURCE.md`、`UPSTREAM.md`、`92e28db` 的原版 vendor 基线及当前工作区；该提交本身已有包装层 `src/`，不能把它与工作区的整仓 diff 当作全部新增代码。
- 当前未提交和未跟踪的业务文件均属于实施基线，必须保留；不修改角色正文、依赖、Pi 设置、真实数据、上游导入记录或 Git 状态。
- 本轮仅交付规划文件。后续实施只进行一次限定于改动文件的静态结构核查；不新增、修改或执行测试，不安装、编译、启动插件或运行迁移。运行验收由用户完成，当前行为也尚无本轮运行证据。
