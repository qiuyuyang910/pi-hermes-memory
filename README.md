# Pi 角色与 Hermes 独立记忆

面向 Pi 1.0.2 的本地扩展，基于 pi-hermes-memory 0.9.10 的 MIT 源码适配。入口为 `src/index.ts`。普通模式使用现有 Hermes 配置与数据；每个角色拥有独立的 Hermes 存储。会话统一保存在 Pi 默认目录，历史索引和查询按角色归属隔离。

## 加载

本次开发不安装依赖、不改变现有 Pi 设置。以下操作由用户执行。

1. 在此目录按运行 Pi 的同一 Node 环境安装 `package.json` 中的依赖。Pi 的三个 SDK 包按 1.0.2 声明 peer dependency，需确保解析到同一版本。
2. 在 Pi 的 `settings.json` 中移除原版 `npm:pi-hermes-memory`、`pi-roles` 及其独立扩展入口，将本插件目录 `E:/Desktop/program/pi-roles-hermes-memory` 加入 `packages`。也可在不加载原版 Hermes 和 pi-roles 的配置中，以 `-e E:/Desktop/program/pi-roles-hermes-memory/src/index.ts` 加载入口。
3. 重启 Pi。已有普通会话仍是普通模式；带本插件归属记录的已有会话会恢复对应角色。首次启动默认普通模式。

不要同时加载两个 Hermes 实现或两个角色管理实现，以免出现重名工具、重复写入和重复提示。模型、认证、原有全局 AGENTS.md、普通 Skills 和 Magic Context 配置仍由 Pi 原机制管理。本插件不复制认证文件。其他记忆扩展的数据行为不在 Hermes 隔离范围内。

依赖安装命令可使用 `npm install`；若主机包的 peer dependency 解析与当前本地 Pi 安装方式冲突，先调整本地依赖解析，确保三个 Pi 包均为 1.0.2。SQLite 的原生模块必须适配运行 Pi 的 Node。适配源码默认不会自动重建或修改依赖，加载失败会明确报错。

## 命令

| 命令 | 行为 |
| --- | --- |
| `/role list` | 列出角色定义 |
| `/role current` | 显示当前模式、记忆和会话位置 |
| `/role prompt` | 查看本会话已加载的完整角色提示词及角色、记忆上下文的注入状态 |
| `/role architect` | 在尚未开始模型请求的会话中选择架构角色 |
| `/role developer` | 在尚未开始模型请求的会话中选择开发角色 |
| `/role off` | 在尚未开始模型请求的会话中选择普通模式 |
| `/role reload` | 在尚未开始模型请求的会话中重读当前角色定义 |
| `/role clear` | 清除当前会话聊天历史和历史索引，进入同一模式的空白新会话 |

会话在尚未开始主会话模型请求时，可通过 `/role <id>`、`/role off` 或 `/role reload` 修改角色。直接在 pwsh 中运行 `pi`、Pi 新建会话、恢复已保存的空白会话均支持；模型和 thinking 初始化记录、文件存在及输入框文字不会使会话锁定。`--new` 已移除，`/role` 不恢复最近历史会话。

插件在 Pi 的 `before_provider_request` 事件中记录锁定状态，即请求发送前的时点；失败、取消或没有回复也不解锁。状态保存在不进入模型上下文的 custom entry 中。锁定后，恢复、重载、压缩和切换分支均不能修改角色；请新建会话，或使用 `/role clear` 清理当前历史并进入新会话。

没有请求状态记录的旧会话，仅含初始化、名称和本插件元数据时允许切换。已有助手消息、工具结果、压缩或分支摘要的会话锁定；只有用户文字却没有请求记录的旧会话也保守锁定，因为无法确认远端是否收到过请求。有明确“尚未请求”记录的会话可以保留未请求的用户文字并切换。

`/role prompt` 在已有上下文及恢复会话中也可使用，展示方式与 `/memory-insights` 相同。它显示已加载的完整角色正文、角色修改是否允许及提示注入状态，修改磁盘文件不会立即改变此输出；成功重读角色后才更新。注入状态表示后续是否允许注入，未启用时显示原因。该命令不写入聊天、不重载角色、不改变注入状态；角色缺失回退时显示原角色标识。

切换等待当前任务结束，再检查锁定状态并验证角色、工具和模型。在当前会话关闭旧 Hermes 实例并初始化目标实例，保留 session ID、会话文件和未请求内容，输入框文字不清除。旧实例关闭时跳过自动提炼；失败时恢复原模式和设置，恢复失败则停止记忆操作并报错。成功后重载同一会话的 Pi 资源，使生成 Skills 的发现目录跟随角色；交接记录使新扩展能够恢复设置或在目标初始化失败时恢复原模式，不创建替代空白会话。

已有会话从 Pi 的恢复入口打开，按保存的归属自动识别角色；角色文件不存在时进入普通模式，原归属不改写。配置损坏、模型不可用或归属矛盾仍报错。

通常恢复已有会话（包括扩展重载）保留其消息、分支、压缩内容、名称和模型选择，仅在需要时记录不进入模型上下文的请求状态。恢复会话及后续对话不注入角色提示或 Hermes 记忆上下文，手动记忆查询仍可用；尚未请求的恢复会话主动选择或重读角色后，启用所选模式的正常注入。缺失角色回退普通模式时停用自动提炼、纠错和回顾，避免把原角色上下文写入普通记忆，原历史也不会被普通模式检索。

`/role clear` 不接受额外参数，也不增加确认弹窗。它等待当前任务结束，通过原生会话替换进入同一模式、同一项目的空白会话；模型和 thinking 按既有切换规则保持。替换取消时，原会话及数据保持不变。

清理删除旧会话的 JSONL 文件、聊天消息、会话元数据和全文历史索引，停止并等待旧实例的后台任务，跳过退出时的记忆提炼和旧会话最终索引。已经保存的记忆、用户资料、项目记忆和所有 Skills 均保留，包括旧会话创建的 Skills。因此 `session_search` 不再返回旧聊天，`memory_search` 仍可查询保留的记忆。

清除标记保存在所属实例既有的 `extension_metadata` 中，不包含聊天正文；自动回填、手动索引、实时索引以及两种历史检索均排除已清除的 session ID。文件删除失败时保留待处理记录，后续初始化继续清理，并明确报告尚未完成；不会将部分清理报告为成功。旧格式会话及尚未落盘的会话也可清理，无需为记忆或 Skills 补充来源信息。

初始化失败会显示错误并停用该会话的记忆操作，业务工具调用也会被拦截。请使用 Pi 新建会话，再选择模式。若 Pi 自身在构造替换会话时失败，主机可能已经使原上下文失效，需要重新启动 Pi 恢复原会话；本插件不会用旧上下文继续写入或改用公共存储。不能确认主机是否接受替换时，保留本次准备的空白会话文件，避免删除主机可能已打开的文件。

## 角色定义

`roles/*.md` 是可修改、删除和添加的示例。文件名是命令标识，只允许小写英文字母、数字、下划线和连字符，最多 64 个字符；`off`、`list`、`current`、`prompt`、`reload`、`clear` 为保留命令。四个示例不是固定角色分类。

```yaml
---
name: 我的角色
description: 说明
tools: [read, grep, find, ls]
---
```

frontmatter 支持 `name`、`description`、`model`、`thinking`、`tools`，正文是追加到现有 Pi 提示的角色提示。`model` 使用完整 `provider/model-id`，必须是当前注册且具有认证的可用模型。`thinking` 可选 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`，实际等级受 Pi 模型能力约束。

省略 `model` 或 `thinking` 时，切换继承切换前的当前选择；没有可继承的 thinking 时才用 `low`。直接恢复会话时保留 Pi 从会话加载的选择。示例角色不指定模型或思考等级。显式配置优先于继承值。

省略 `tools` 时使用普通模式工具集；指定时限制模型的业务工具，并通过 `tool_call` 拦截未允许的调用。所有原版 Hermes 工具始终加入允许列表，包括记忆读写、完整记忆查询、会话历史搜索和自身 Skills 管理。返回普通模式恢复普通工具集。项目 AGENTS.md 仍由 Pi 加载，角色提示不会替代项目指令。

设置 `tools: ["*"]` 时，启用 Pi 当前提供的所有可用工具，并取消该角色的工具列表拦截。只要列表包含独立的 `"*"`，就按全部工具处理；不支持 `mcp_*` 等名称匹配模式。修改后在尚未开始模型请求的会话中执行 `/role reload`，或新建会话再选择该角色。Pi 自身的工具可见性、项目指令和授权限制仍然生效。

工具选择和调用拦截属于 Pi 扩展级控制。其他扩展自行执行代码或直接访问文件系统不受角色工具列表约束。

## 存储与原文

普通模式继续读取 `~/.pi/agent/hermes-memory-config.json`，包括现有 `D:/pi-hermes-memory` 数据。所有会话使用 Pi 默认布局 `~/.pi/agent/sessions/<Pi 项目目录>/`，尊重 `PI_CODING_AGENT_DIR`。普通模式和角色的新活动项目记忆目录使用规范化实际工作目录的 SHA-256 标识，同名不同路径不会混用。旧普通项目记忆不自动迁移；旧条目仍可通过 `memory_search` 按原项目名称查询。

```text
.state/roles/<id>/
  pi-hermes-memory/       MEMORY.md、USER.md、SQLite 历史和记忆索引、skills/
  projects-memory/<项目标识>/
```

会话 custom entry 持久化角色、项目、规范化目录和记忆存储根。普通模式只能索引和检索普通会话，各角色只能索引和检索自身会话；数据库查询及直接扫描 JSONL 的 anchor 查询均过滤归属。损坏的标记不会作为普通会话导入。该限制针对 Hermes 查询，不限制通用文件读取工具或 Pi 的会话恢复界面。角色存储重定向到其他实际路径会被拒绝。`.state/handoff/` 仅保存空白会话替换所需的非敏感设置，初始化后删除。

### 旧角色会话迁移

关闭所有使用本插件的 Pi 实例，在插件目录执行 `node scripts/migrate-role-sessions.mjs`，使用与 Pi 相同的 Node 和依赖环境。脚本将 `.state/roles/<id>/sessions` 下的会话迁入 Pi 原生项目目录，保留内容、会话 ID 和角色归属，更新所属数据库的文件索引路径及待清除记录。旧会话在迁移前会提示迁移要求，不自动移动文件。

脚本先检查归属和目标冲突，再逐文件复制、核对内容、更新索引并移除源文件。不同内容的目标文件不会覆盖；中断后关闭 Pi 再执行同一命令继续。进度保存在忽略的 `.state/session-migration.json`，不移动记忆或 Skills。迁移脚本尚未运行验证。

`memory_search` 返回命中条目的完整已保存 `content`，不对单条内容截断；结果数量仍沿用 Hermes 的默认 10 条、最多 20 条。工具名不变，但执行对象随实例切换。`session_search` 查询所属实例的聊天历史索引；记忆条目与聊天原文是两个不同的数据源。`/memory-insights` 保留概览和预览用途，不能当作完整原文查询。

自然语言记忆查询优先使用 FTS AND，再尝试 FTS OR；均无命中时按原始词项执行字面 LIKE OR 查询，支持多个单字、双字中文词。单字、双字中文整串继续使用专门的短词回退。LIKE 沿用项目、目标、类别过滤及数量限制，不绕过角色数据库隔离；显式 FTS 运算符查询保持原有语义。

### 新增记忆日志

所有由 Hermes 成功新增的记忆会追加到当前模式实际记忆根目录下的 `logs/memory-additions.log`。普通模式沿用配置或默认记忆目录；角色日志位于 `.state/roles/<id>/pi-hermes-memory/logs/memory-additions.log`。项目记忆也记录在所属模式的这份日志中，其 `markdownPath` 指向实际项目记忆文件。

日志为 UTF-8 JSON Lines，每个新增条目一行，包含保存时间 `savedAt`、模式或角色 `role`（普通模式为 `null`）、项目路径 `projectPath`、`sessionId`、记忆目标 `target`、完整已保存条目 `content`（含 Markdown 日期元数据）、Markdown 绝对路径 `markdownPath` 和 SQLite 定位信息 `sqlite`。SQLite 信息包含数据库绝对路径 `databasePath`、表名 `table`、条目 ID `entryId`、状态 `status` 及原因 `reason`。没有可用的会话 ID 时记录 `null`。

日志覆盖手动工具、自动回顾、纠错、压缩前提炼和退出提炼的成功新增，包括全局记忆、用户资料、项目记忆和失败经验。回填、启动同步、重复添加、替换、删除和整理不会记录成新增；原子操作中被移除或未最终保存的新增条目也不会记录。

Markdown 保存后才记录日志。SQLite 同步成功且确认对应条目时，`status` 为 `indexed`；同步异常或无法确认时为 `unconfirmed`，`entryId` 为 `null`，记忆仍保留在 Markdown。日志写入失败会报告“记忆已保存，日志写入失败”，不回滚记忆。每次追加使用现有锁机制，写入完成后记忆操作才返回；实例关闭等待在途操作。日志不参与记忆或会话检索，`/role clear` 保留日志，Git 忽略 `*.log`。

保留 Hermes 的记忆读写、用户资料、项目记忆、历史搜索、回顾、纠错、整理、生成 Skills 和原有命令。角色配置只调整业务工具，不禁用自身记忆写入。角色 Skills 只从当前实例的全局和当前项目目录发现，不迁移或自动加载另一模式的 Hermes Skills。

普通模式沿用现有 Hermes 配置，角色沿用其非路径设置并覆盖为角色专属路径。默认 policy-only、full、回顾 20 轮／30 次工具调用；后台 thinking 默认 off，独立于主角色 thinking。后台调用固定 direct；失败显示诊断，不能回退到子进程。手动和自动整理均使用当前模型上下文。关闭流程幂等，等待在途操作、回顾、回填和实时索引结束后关闭所属数据库。

## 用户运行验收

本次只进行静态核查，没有安装、编译、启动 Pi 或执行测试。实际加载和隔离效果尚未验证。用户运行验收应覆盖：

- 普通模式与两个角色分别写入不同记忆、资料和 Skills，再各自查询；角色历史搜索只出现自身会话。
- 使用 `memory_search` 查询长记忆条目，确认完整内容；区分 `/memory-insights` 预览和 `session_search` 聊天历史。
- 改变当前主模型和 thinking 后切换到未指定它们的角色，确认继承；显式设置后确认覆盖。
- 直接启动 Pi、新建会话或恢复已保存的空白会话，在请求前可选择角色或普通模式，ID、文件、未请求内容和输入框文字保留；`--new` 被拒绝。
- 模型请求开始后，包括失败或取消时，均不能切换或重读角色；重载、恢复、压缩和切到空分支后仍锁定。没有请求记录但已有用户文字的旧会话保守锁定。
- 使用 Pi 恢复角色会话，确认归属恢复，后续对话不注入本插件提示或记忆；删除角色定义再恢复，确认进入普通模式且原上下文、归属保留，没有自动提炼到普通记忆。
- 在同名不同实际路径的项目中使用同一角色，确认项目记忆和 Pi 会话目录不同。
- 切换取消、初始化失败、重读角色、扩展重载和退出后确认没有后台串写、公共目录回退或残留在途写入。
- 修改、添加、删除示例角色，确认定义生效；只读角色的业务写入工具被拦截，自身记忆工具仍可用，项目指令仍有效。
- 在普通模式和角色模式执行 `/role clear`，确认旧聊天消失，两种历史检索均不能召回；重启、自动回填和手动索引后仍不能召回。确认已保存记忆、资料、Skills 及其他会话保持可用，并覆盖取消、未落盘会话、删除失败、初始化失败和拒绝额外参数的情况。
- 关闭 Pi 执行旧会话迁移，确认内容、ID、归属和最近的 Pi 历史恢复保持可用，索引路径更新；覆盖目标冲突及中断后重试。
- 检查所有新增来源及记忆目标的日志，确认正文完整、角色隔离、文件与数据库定位准确，重复和同步不记为新增；覆盖索引失败、日志写入失败、并发追加、退出等待及 `/role clear` 保留日志。

源码由 Git 管理并推送到自己的仓库。`roles-hermes` 保存角色插件，`hermes-upstream` 保存原版 Hermes 基线；后续上游升级流程见 [UPSTREAM-UPDATE.md](UPSTREAM-UPDATE.md)。`.gitignore` 排除记忆、会话、数据库、交接状态、凭据、日志与依赖。上游来源和适配范围见 `SOURCE.md`，当前基线引用与提交号见 `UPSTREAM.md`。
